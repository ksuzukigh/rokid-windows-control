# リリースチェックリスト

## 方針

このチェックリストは一般公開の可否を判断するために使用する。すべて完了し、利用者が明示的に承認するまで、GitHub Releasesの公開版または公開プレリリースを作成しない。

ローカルおよびGitHub Actionsで未署名の候補ZIPを作成して検証することはできる。ただし、それを公開済みとして扱わない。

## 1. UI調整

- [ ] 起動時のモード選択が分かりやすい
- [ ] メイン画面の配置、余白、文字サイズ、色を確認した
- [ ] 「接続中」「再接続中」「終了中」の状態が分かりやすい
- [ ] エラーの内容と、利用者が次に行う操作が分かりやすい
- [ ] ボタン、選択項目、リンクをキーボードでも操作できる
- [ ] 表示倍率100%、125%、150%で文字切れや操作不能がない
- [ ] 通常表示とライブ映像表示の見た目を確認した
- [ ] Rokid上の選択リングと合成映像を実機で確認した
- [ ] 利用者がUIの最終状態を承認した

## 2. 機能と実機

- [ ] 技術試験T01からT18までがPASS
- [ ] ダブルSpace操作を実機で手動確認した
- [ ] USB接続とWi-Fi接続を最終版で確認した
- [ ] Wi-Fi瞬断後の自動復帰を最終版で確認した
- [ ] Ctrl+QとAlt+F4のクリーン終了を最終版で確認した
- [ ] PC側とRokid側に残存プロセスがない

## 3. 配布物

- [ ] Releaseビルドが警告0、エラー0
- [ ] セルフテストがすべて成功
- [ ] 自己完結型Windows x64 ZIPを生成
- [ ] ZIP内の必須ファイルと第三者ライセンスを確認
- [ ] 自作のEXEとDLLへ信頼されたRSAコード署名を付与
- [ ] 署名とタイムスタンプを検証
- [ ] ZIPのSHA-256を生成して再照合
- [ ] 別のWindows 11環境で展開、起動、終了を確認

## 4. 公開承認

- [ ] バージョン番号とリリースノートを確認
- [ ] 公開するZIPとSHA-256を利用者が確認
- [ ] 公開範囲がGitHub Releasesであることを確認
- [ ] 利用者が一般公開を明示的に承認
