# Windows 0.2.0-rc.2 の変更と実機確認

2026年10月3日。Mac版1.2.7（コミット `fc5830a`）の機能変更をWindowsへ移植し、アプリ一覧の初回キー操作を修正した。

[更新候補版のダウンロード](https://github.com/ksuzukigh/rokid-windows-control/releases/tag/v0.2.0-rc.2)

## 主な変更

- Rokid ZOOM IN CAMERAの撮影画面へカラー表示を切り替え、終了後はライブ映像へ戻る。現在の最前面画面を判定し、履歴だけでは切り替えない。
- M・H・Aボタン、操作案内、見やすさ調整を映像とは別の下部欄へ配置。背景なし・カメラ表示でも案内を映像の外へ配置する。
- Homeの現在の操作領域を読み取り、固定座標に依存しないナビゲーションへ変更。一意に確認できない領域は操作しない。
- 純正の音量・明るさ画面では、一覧の選択中以外でも左右キーで調整できる。
- 準備済みR08 Access Bridge 2.0.1の補助ファイルを検証し、旧監視を停止してショートカット補助と方向橋渡しを復旧。APK、ペアリング、個人設定を保持する。
- R08の既知の設定で残った固定5555番の接続を暗号化接続から閉じて再探索する。暗号化されていない接続は採用しない。
- 純正カメラを開いた状態でライブ映像を開始した場合も、カラー撮影画面から開始し、閉じた後にライブ映像へ戻る。

## 初回キー操作の修正

rc.1では、Aで一覧を開いた直後の最初の左右キーが効かない、または隣の項目を飛ばすことがあった。Androidがタッチ入力状態から復帰するときの入力先と、YodaOSに表示された選択項目が食い違うことが原因だった。

rc.2では、一覧を開いたときの表示項目と位置を保持し、キー入力先をその項目へ同期する。YodaOSが以前の位置へ戻した場合は現在の一覧を読み直して元の位置へ戻し、位置・表示名・入力先の一致を連続して確認する。処理はアプリ一覧に限定し、対象が一意でない画面では操作しない。同期中にアプリを起動せず、R08のアクセシビリティサービスも抑制しない。

## 確認環境

- Windows x64、OSビルド `10.0.26300.0`、.NET SDK 10.0.302、scrcpy 4.1。
- Rokid RV101（RG-glasses）、Android 12、480×640。
- 開発用USB接続と暗号化Wi-Fi接続。夜間はUSBを外した状態で確認。
- Rokid ZOOM IN CAMERAとR08 Access Bridge 2.0.1を準備した実機。

途中で失敗した結果と修正後の成功結果は分けて保存した。初回キーの最終回帰試験、およびrc.2配布用EXEのWindowsキー入力確認は、ともに `Passed: true`。

## 開発者向けの再実行

通常の検証は `tools/verify.ps1`、実機のキー回帰試験は次のコマンドで実行する。

```powershell
dotnet run --project tools/RokidControl.HardwareProbe -c Release -- --keyboard-regression <実機のADB接続先> <保存先>
```

キー回帰試験は実機の画面を移動し、音量・明るさを一時変更した後に元へ戻す。結果は保存先の `result.json` と `session.log` に記録する。Java補助処理の再生成手順は [DeviceHelper](../DeviceHelper/README.md) を参照。
